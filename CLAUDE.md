# Don't Miss Your Flight

## Repos
- Frontend (this repo): `C:\ThreeJS\Dont-miss-your-flight\Dont-miss-your-flight`. Backend: `..\Dont-miss-your-flight-backend` (Colyseus + MongoDB). `net.js` links them: a signed-in player's progress (`store.snapshot()`) saves on the server, guests (and serverless sessions) in localStorage, each account also mirrored in the browser under its own key; the Daily Reward is server-authoritative for accounts (`daily` / `claimDaily`), local for guests; trolls are relayed to everyone in the room (`troll` -> `trolled`). ## Current state
Opening taxi cutscene -> gameplay at the terminal entrance -> check-in hall with a live queue (join, Position In Line, Skip Line, YOUR TURN) -> desk conversation (`checkin.js`: Where to? postcards, bag on the scale, 15 questions from `QUESTIONS`, upgrade offer, seat map, boarding pass with CHECKED IN stamp) -> security hall (`security.js` + `airport/securityHall.js`: line, tray on the X-ray rollers, metal detector always beeps for you, search mat with a timed pat-down and "FOUND ON YOU!" items, some tagged from your check-in answers, Skip Search, ALL CLEAR). -> the concourse + your gate (`airport/gates.js` + `boarding.js`: "PLANE ARRIVING IN" clock + Skip Time, seats you can sit in, waiting passengers with their own timers, the Sky Lounge with a bouncer + bartender, then a plane-arrival cutscene, the boarding line, gate agent + scanners, jet bridge) -> "now boarding" -> the flight (`airport/cabin.js` + `flight.js`: take-off cutscene, cruise timer + Skip Time, landing) -> the destination street (`airport/city.js`, styled per city in `CITIES`) with Fly Again back to the curb. Every price is in coins (`PRICES`, `SUITCASES`), never premium currency.

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the ground (`BEACH`, `WATER`, `SPAWN`, `SPAWN_FACING`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest, `getToken()` for the backend), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`, `master_volume`), avatar + proportion change events (`lookJson()` / `skinTextureUrlFor()` for the other passengers), portal player events (`respawn_request`, `play_emote` / `stop_emote` -> `onEmote`), the avatar customizer, the matchmaker helpers (`resolveServerEndpoint`, `locateRoom`, `updateRoom`), friend toasts (`playerJoined` / `playerInRoom`), ad breaks (`onAdBreak`: main pauses the loop + `setAdMute`), screen ads (`declareScreens` gameplay + results; `showScreenAd('results')` 3.5 s after landing), rewarded ads (`showRewarded`; Shop "Watch an ad" button -> backend verifies the token -> `ADS.reward.coins`), the death screen (`deathScreen()`: the Kill All knockout waits for its countdown), leaderboards (`define(LEADERBOARDS)`; the backend submits scores), emotes (`registerFeature('emotes')`, catalogue `emoteClip(id)`, played by `emotes.js`) and chat bubbles (`onChat` -> `crowd.say` over you / the passenger who spoke). Local dev: `vite.config.js` injects `window.BLOXITY_ENV` (dev server only). Gems are never used.
- **Multiplayer (fellow passengers)**: the other real players are the passengers; the staff (agents, officers, clerks, bouncer, bartender, cabin crew) are bots. `net.js` sends this client's roster entry (`setPresenceSource` in main: `pose` ~10/s from the drawn avatar, `trip` = zone airport|cabin|city + dest, the line you stand in, the desk / lane / mat / scanner you hold, suitcase, hat, VIP, backpack, bag; `setAvatar`; `emote`) and identifies with the Bloxity token (`dev-<name>` locally, `?dev=<name>` for a second tab). `remote.js` draws everyone else (base rig + their cosmetics, animator with sit / T-pose / KO / carry overlays, emotes, name tag, hat, backpack, suitcase; interpolated `REMOTE.delay` behind; cabin / city only for the same flight; nearest `REMOTE.maxDrawn`). Lines: `syncRemoteLine` (linepath.js) puts real passengers into each client's check-in / security / boarding line at the distance they stand, so they count for your Position In Line (`e.remote` entries are skipped by the shuffle loops and never dispatched; `lineNpcs` makes them solid); held spots (`remote.held('desk:N' | 'lane:N' | 'mat:N' | 'scan')`) are never handed out. There are NO bot passengers (`PASSENGERS.bots: false`): no seeded line / desk / security / gate / lounge sitters, no arrivals, no cabin passengers; only staff bots and the destination city's street pedestrians. `remote.botShare()` is 0 then (with `bots: true` it is 1 - real passengers in the airport / `PASSENGERS.fullAt`, a backfill gating the seeds, queue arrivals, security extras, gate sitters / walkers / boarding extras and cabin seats). `store.flights` counts landings (Flights Taken leaderboard). Run two players locally: launch configs `mp-backend` (port 2591) + `mp-client` (port 5261), tabs `?dev=alice` / `?dev=bob`.

## Files (`src/`)
- `main.js`: boot = Bloxity SDK -> renderer -> Rapier -> lighting, fx, clouds, `airport/exterior.js` (curb, roads, canopy, facade + sliding doors, car park, tower, parked buses/taxis, traffic, planes, birds, pigeons), `airport/interior.js` (hall, stanchions, desks with scale read-outs + belts, departure boards, signs, QUEUE HERE / CHECK IN markers), `crowd.js`, player body, `suitcase.js`, `hud/hud.js`, `queue.js`, `powers.js` -> avatar -> `cutscene.js` -> loop `tick(dt)`. Dev: `__game.advance(seconds)` steps the game by hand (use it when the preview tab is not painting), plus `teleport`, `queue`, `crowd`, `store`, `powers`, `hud`.
- `cutscene.js`: timeline-driven taxi arrival (4 shots, letterbox, title, Skip). Drives the hero taxi from `exterior.taxi`, the avatar through `cutscene.actor` (main copies it into the player group + animator, incl. pose overlays), then main blends the camera into the chase cam (`CUTSCENE.blendOut`).
- `crowd.js`: every NPC (passengers + desk agents) in ~12 InstancedMeshes, pose computed per frame (walk, idle, type, wave, scare, KO, pulling a bag); pooled speech bubbles (`say`) and name tags for the nearest 12.
- `queue.js`: the line as distance `s` along `QUEUE.path`; arrivals, shuffling, desk service (agent lines, belt bags), and the player's states free -> line -> turn -> desk -> checked (player walked by `player.auto`). `player.frozen` holds the body during the cutscene.
- `lineBlockers.js`: people in lines are solid. Every NPC in the check-in / security / boarding line (`lineNpcs(out)` on each) gets a pooled kinematic capsule (`QUEUE.block`) the player's controller collides with, so you can't walk through a line to cut ahead. In the three shuffle loops nobody steps closer than `QUEUE.spacing` to the one ahead, and people behind the player wait (`lineStepClear`) instead of walking into them; a blocker that still ends up inside the player (Skip Line teleport) stays off until they're apart.
- `guards.js` (`GUARDS` in config): no skipping a step. Three checkpoints: the doorway into security (needs check-in), the screening lanes behind the security line (needs to be called from the line), the doorway to the gates (needs security cleared). Each has a physical barrier whose collider is solid only to a player who isn't allowed (laser gates: scanner pedestals, beams, energy curtain, beacon, floor decal; the lanes: a laser fence of bollards), NPCs pass and the beams step aside, plus a hand-built guard (baked per body segment; cap, sunglasses, earpiece, SECURITY hi-vis vest, duty belt) who escalates: instruct (whistle, point, toast) -> LAST WARNING -> rushes and shoves you back (`player.stun` knock-back, dust, impact stars, shake, red vignette). Inside a closed zone you're grabbed (in `chase`) or radioed in and escorted out (fade + teleport to `safe`). Cutting in line (`GUARDS.cutting`): standing in a line's lane (near its path, past the join point) ahead of anyone waiting in it (bots or real players from `lineNpcs`) without having joined -> "NO CUTTING!", the bots behind complain, the line's guard (check-in: entry guard, security: lanes guard, boarding: a marshal at the VIP priority lane) whistles and points; moving up the line or loitering -> escorted to the join zone (so you join at the back). The priority lane is VIP-only (`store.has('vip')`). Synth sounds via `registerSfx` (whistle, laserZap, deny, radio, shove, grunt, hey, siren, bootStep, boo). `guards.reset()` on Fly Again; dev: `__game.guards` (`checkpoints`, `lines`, `marshal`).
- `hud/`: `hud.js` + `hud.css` (HUD, Announce / Emoji / purchase confirm windows), `windows.js` + `windows.css` (Daily Rewards 7-day calendar `DAILY`, Shop with Passes / Trolls / Jobs / Bags tabs `SHOP`, Destinations `FEATURED_DESTINATIONS` + `DEST_SOON`), `art.js` (card + city postcard SVGs), `icons.js` (inline SVG). `store.js`: coins, suitcases, job hats, passes, visited codes, timed rewards (`grantTimed`/`timeLeft`/`has`), offline daily calendar, `snapshot()`/`hydrate()`.
- `tools.js` + `tools.css`: hotbar (keys 1-5, F/click/USE to use, Q to put away) for Air Horn, Handcuffs, Gravity Gun, Ban Hammer, Grapple Hook (`TOOLS`); NPCs held by tools are "pinned" (overrides their position after queue/security update, before `crowd.update`; crowd modes `cuffed` / `float`); job panel (Security: Search / Add Time / Let Go; Pilot: Takeoff / Turbulence / Announce, `JOBS`); VIP (tag, 2x earned coins in `store.addCoins`, auto-front of every line); destination visited on clearing security; troll routing (`useTroll` = run + relay, `receive` = someone else's). `trolls.js` + `trolls.css`: Lost And Found Rain, Jet Flyover, Coin Shower, Airport Party, Let It Snow, plus jumpscare / knockout / turbulence / camera shake (`late()` after the camera update). `audio.js` `registerSfx` adds one-shots from other modules.

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
