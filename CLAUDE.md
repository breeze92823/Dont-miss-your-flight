# Don't Miss Your Flight

## Repos
- Frontend (this repo): `C:\ThreeJS\Dont-miss-your-flight\Dont-miss-your-flight`. Backend: `..\Dont-miss-your-flight-backend` (Colyseus + MongoDB). `net.js` links them: a signed-in player's progress (`store.snapshot()`) saves on the server, guests (and serverless sessions) in localStorage, each account also mirrored in the browser under its own key; the Daily Reward is server-authoritative for accounts (`daily` / `claimDaily`), local for guests; trolls are relayed to everyone in the room (`troll` -> `trolled`). Dev talks to `ws://localhost:2567` (`VITE_SERVER_URL_DEV` overrides; launch configs `flight-shop` + `flight-backend` use port 2579).
- Reference screenshots for the game are the ones the user pastes in chat (a Roblox airport game). Never copy its branding: the airline here is `AIRLINE` ("skyhop air"), the airport "Skyport".

## Current state
Opening taxi cutscene -> gameplay at the terminal entrance -> check-in hall with a live queue (join, Position In Line, Skip Line, YOUR TURN) -> desk conversation (`checkin.js`: Where to? postcards, bag on the scale, 15 questions from `QUESTIONS`, upgrade offer, seat map, boarding pass with CHECKED IN stamp) -> security hall (`security.js` + `airport/securityHall.js`: line, tray on the X-ray rollers, metal detector always beeps for you, search mat with a timed pat-down and "FOUND ON YOU!" items, some tagged from your check-in answers, Skip Search, ALL CLEAR). -> the concourse + your gate (`airport/gates.js` + `boarding.js`: "PLANE ARRIVING IN" clock + Skip Time, seats you can sit in, waiting passengers with their own timers, the Sky Lounge with a bouncer + bartender, then a plane-arrival cutscene, the boarding line, gate agent + scanners, jet bridge) -> "now boarding" -> the flight (`airport/cabin.js` + `flight.js` + `cabinCrew.js`: a widebody with First / Business / Premium / Economy cabins, crew who keep you in your class (or sell you an upgrade), meal service, sneaking forward; take-off cutscene, cruise timer + Skip Time, landing) -> the destination street (`airport/city.js`, styled per city in `CITIES`) with Fly Again back to the curb. Every price is in coins (`PRICES`, `SUITCASES`), never premium currency.

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the ground (`BEACH`, `WATER`, `SPAWN`, `SPAWN_FACING`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest, `getToken()` for the backend), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`, `master_volume`), avatar + proportion change events (`lookJson()` / `skinTextureUrlFor()` for the other passengers), portal player events (`respawn_request`, `play_emote` / `stop_emote` -> `onEmote`), the avatar customizer, the matchmaker helpers (`resolveServerEndpoint`, `locateRoom`, `updateRoom`), friend toasts (`playerJoined` / `playerInRoom`), ad breaks (`onAdBreak`: main pauses the loop + `setAdMute`), screen ads (`declareScreens` gameplay + results, the results slot at `middle-right` so it never covers the bottom-centre Fly Again button; `showScreenAd('results')` 3.5 s after landing), rewarded ads (`showRewarded`; Shop "Watch an ad" button -> backend verifies the token -> `ADS.reward.coins`), the death screen (`deathScreen()`: the Kill All knockout waits for its countdown), leaderboards (`define(LEADERBOARDS)`; the backend submits scores), emotes (`registerFeature('emotes')`, catalogue `emoteClip(id)`, played by `emotes.js`) and chat bubbles (`onChat` -> `crowd.say` over you / the passenger who spoke). Local dev: `vite.config.js` injects `window.BLOXITY_ENV` (dev server only). Gems are never used.
- **Multiplayer (fellow passengers)**: the other real players are the passengers; the staff (agents, officers, clerks, bouncer, bartender, cabin crew) are bots. `net.js` sends this client's roster entry (`setPresenceSource` in main: `pose` ~10/s from the drawn avatar, `trip` = zone airport|cabin|city + dest, the line you stand in, the desk / lane / mat / scanner you hold, suitcase, hat, VIP, backpack, bag; `setAvatar`; `emote`) and identifies with the Bloxity token (`dev-<name>` locally, `?dev=<name>` for a second tab). `remote.js` draws everyone else (base rig + their cosmetics, animator with sit / T-pose / KO / carry overlays, emotes, name tag, hat, backpack, suitcase; interpolated `REMOTE.delay` behind; the cabin is shared by every flight in the air (name tags add the passenger's destination, "Bob · Tokyo"; `flight.board()` moves you to the nearest free seat if `remote.seatTaken` says a real passenger already sits in yours), the city only for the same destination; nearest `REMOTE.maxDrawn`). Lines are **server-ordered** (backend `lines.ts`): main calls `net.wantLine(kind)` every frame, which sends `joinLine` / `leaveLine` so the server's `line` + `ticket` (join order) match the line you stand in; `skipLineOnServer` (Skip Line / VIP) moves your ticket to the front. `syncRemoteLine(..., myTicket(kind))` (linepath.js) puts real passengers into each client's check-in / security / boarding line and re-sorts the real ones (you + them) by ticket, so every client draws the same order; bots keep their positional places. Real passengers are never solid (`lineNpcs(out, true)` = bots only, for lineBlockers; guards still see everyone). Online only bots are dispatched by the local head-of-line code; you are called by the server: `lineTurn(kind).update(...)` asks `callMe { kind, keys }` (throttled `QUEUE.callEvery`) once you stand at your spot among the first `QUEUE.callDepth` with enough free spots for your place (2 free desks = the first two are called at once; called from 2nd/3rd place you walk via the head of the line), and the server answers `called { key }` with the spot it hands you (never one held or just granted to someone else). Search mats go through `spotClaimer()` -> `claimSpot`. Offline (no server) the lines run locally as before. Joining always walks you along the lanes to your spot (no shortcut, even when the line is empty: walking the line is the game); stepping out takes `QUEUE.leaveHold` s of pushing. Nobody gets stuck behind a gone or AFK player: `net.js` sends an `alive` beat from the game loop every `REMOTE.aliveEvery` s (and `away` at once when the tab hides), and `active` every `REMOTE.activeEvery` s while there is player input (keys / mouse / touch); the server flags `away` (no beat for 5 s, or a dropped connection in its reconnect window) and `idle` (no input for 60 s). Away passengers are left out of every line + held spot (name tag "(away)"); idle ones keep their ticket but the server passes over them and their held spot counts as free (name tag "(idle)", your own client toasts "Still there?" and stops asking to be called). Offline, `syncRemoteLine` still drops a member who stands still with free room ahead for `QUEUE.stall.after` s (`m.stalled`); the line's guard walks over to stuck ones and waves the line on (`GUARDS.cutting.clearLine`). There are NO bot passengers (`PASSENGERS.bots: false`): no seeded line / desk / security / gate / lounge sitters, no arrivals, no cabin passengers; only staff bots and the destination city's street pedestrians. `remote.botShare()` is 0 then (with `bots: true` it is 1 - real passengers in the airport / `PASSENGERS.fullAt`, a backfill gating the seeds, queue arrivals, security extras, gate sitters / walkers / boarding extras and cabin seats). `store.flights` counts landings (Flights Taken leaderboard). Run two players locally: launch configs `mp-backend` (port 2591) + `mp-client` (port 5261), tabs `?dev=alice` / `?dev=bob`.

- `lineBlockers.js`: people in lines are solid. - `guards.js` (`GUARDS` in config): no skipping a step. Three checkpoints: the doorway into security (needs check-in), the screening lanes behind the security line (needs to be called from the line), the doorway to the gates (needs security cleared). Each has a physical barrier whose collider is solid only to a player who isn't allowed (laser gates: scanner pedestals, beams, energy curtain, beacon, floor decal; the lanes: a laser fence of bollards), NPCs pass and the beams step aside, plus a hand-built guard (baked per body segment; cap, sunglasses, earpiece, SECURITY hi-vis vest, duty belt) who escalates: instruct (whistle, point, toast) -> LAST WARNING -> rushes and shoves you back (`player.stun` knock-back, dust, impact stars, shake, red vignette). Inside a closed zone you're grabbed (in `chase`) or radioed in and escorted out (fade + teleport to `safe`). In a line's lanes without queueing (`GUARDS.cutting`): standing in a line's lanes (`inLane`: near its path, past the join point; the boarding lanes only once boarding opens) while not part of that line (jumped the stanchion fence, or stepped out of the line and stayed; walking in through the entrance joins you) -> after `grace` (`hopGrace` when you landed there from a jump: `trackHops` flags landing in the lanes through the air from outside, or in a lane `hopAhead` m further up; jumping back out doesn't count) the line's own guard (`lineGuards`: officer diaz beside the check-in serpentine, officer kim beside the security one; boarding: the marshal at the VIP priority lane) walks over and gives WARNING 1/2, then LAST WARNING 2/2 (`warnGap`, sooner if you push further up the line), then runs in, grabs you and sends you BACK TO THE START: the line's entrance (join zone), so you queue again from the back and walk the whole path (fence jumpers get "No jumping the fence!" lines, `hopWarn1/2`). Stepping or jumping out of the lanes in time ends it ("Thank you"); strikes are remembered for `memory` s, so coming straight back resumes at the next step. ## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **HUD layout on phones (keep the middle of the screen clear)**: `hud.js` `layoutReserved` turns `bloxity.onReservedAreas` into CSS vars on `.hud` (`--rz-left` / `--rz-right` = how far down the toolbar + chat feed reach at each edge, `--top-x/--top-y` for Board The Plane (with the plane clock + "You're in line!" under it: always at the top, clear of the toolbar row only, not the chat feed, so on portrait phones it sits right under the toolbar instead of over the player), `--band-x/--band-y` for the job banner: beside the toolbar when it fits, else under it); position new top / left / right HUD pieces with them. On phones (`max-width: 700px` or `max-height: 560px`) Be Security / Be Pilot + the six powers fold into the `.hud-tray` behind one Powers button (`.tray-btn`, `tray-open`; on bigger screens the tray is `display: contents`). Portrait touch: left column tiles + coins, right column mute / day / respawn / Powers / boarding pass, hotbar + USE just above the joystick and jump cluster (bottom ~156px), Skip Line / Skip Time / Fly Again as compact one-row buttons at `--act-y` (just above the joystick, or above the hotbar when it shows) with prompts stacked over them, so the player in the middle stays visible; the plane countdown is one compact line (`has-timer` hides the duplicate "Plane arriving in" label). Landscape touch: tiles in a row under the chat feed with the coins beside them, one bottom row (joystick, hotbar, Skip Line / Skip Time moved right, jump cluster). The agent panel goes compact with side-by-side answers in landscape and the side buttons hide during it (`dialog-open`). Never give an element the bare class `win` (that is the modal window style). Check with every element's rect at 320x568, 375x812, 812x375, 667x375, tablet and desktop: no overlapping buttons, nothing in the reserved areas.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
